# PROJECTS.md

> Version: 2.0
>
> Purpose:
>
> Define the standard structure for every project showcased in the portfolio.
>
> Every project should tell a complete engineering story,
> not simply display screenshots.
>
> Visitors should understand:
>
> • What problem existed
> • Why it mattered
> • How it was solved
> • What technologies were chosen
> • What challenges were overcome
> • What impact was delivered

---

# Philosophy

A project is not a gallery item.

A project is evidence.

Evidence of:

• Engineering ability

• Product thinking

• System design

• Problem solving

• Code quality

• Communication

Every project should answer:

"Why should I trust this engineer?"

# Featured Project Criteria

A project becomes "Featured" only if it satisfies at least four of the following:

✓ Production deployment

✓ Real users

✓ Complex architecture

✓ Authentication

✓ Performance optimization

✓ Responsive

✓ Accessibility

✓ Team collaboration

✓ Multiple integrations

✓ Business impact
